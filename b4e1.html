Start here — si le sujet est nouveau pour vous

Claude est la famille de modèles de langage d'Anthropic. On peut l'atteindre par une fenêtre de conversation, une application de bureau, une extension de navigateur, un complément pour Word ou Excel, un outil en ligne de commande pour développeurs, un service d'agents hébergé, et par les nuages d'Amazon, de Google et de Microsoft. Anthropic parle tour à tour de « surfaces », de « plateformes » et de « fournisseurs », et les noms changent tous les quelques mois.

Cela compte parce que le choix de la porte décide de trois choses qu'on confond facilement : où tourne réellement le travail, qui envoie la facture, et ce que deviennent vos données. Deux personnes qui « utilisent Claude » peuvent être dans des situations très différentes sur ces trois points.

Cette note résume en une page la carte complète publiée en anglais : quatre familles de portes, une table, l'idée qui rend la carte lisible, et quatre questions pour choisir.

1. La question derrière la confusion

Read this note in English, with its full argument and twenty-seven sources: English version [S1].

Quiconque utilise Claude depuis quelques semaines finit par se poser la même question : pourquoi « Claude » est-il vendu à la fois comme une application, un outil de développement, une « session cloud » et un produit Amazon ? La réponse tient en deux idées. D'abord, le moteur est le même partout : Anthropic écrit que « Claude Code runs the same underlying engine everywhere, but each surface is tuned for a different way of working » [S3]. Ce qui change, c'est l'environnement dans lequel ce moteur est lancé : un dossier sur votre machine, ou un conteneur éphémère dans le nuage d'Anthropic. Ensuite, il faut séparer deux questions que le marketing confond : où tourne la session, et qui la déclenche et la paie.

La carte est volontairement datée. Dans le mois qui précède le 11 octobre 2026, Anthropic a fusionné deux de ses produits grand public en un seul [S5], lancé une promotion de crédit qui expire le 4 novembre [S6], et conservé au moins une page de documentation qui décrit encore l'ancienne disposition. La méthode de lecture, elle, ne périme pas.

2. La carte en une table

Quatre familles couvrent toutes les portes. Les applications Claude (web, bureau, mobile, extension Chrome, compléments Office), payées par abonnement. Claude Code, l'agent pour le logiciel et, de plus en plus, pour tout travail sur fichiers, atteint par un terminal, un éditeur, l'application de bureau, le navigateur, le téléphone ou Slack. La plateforme développeur (API et service d'agents hébergé), payée au jeton. Les places de marché des nuages (Amazon Bedrock, Google Cloud's Agent Platform, ex-Vertex AI, Microsoft Foundry), facturées par ces fournisseurs.

Trois constats. Les portes qui tournent sur votre propre machine sont minoritaires. Il n'y a que deux façons de payer, l'abonnement ou la consommation, et chaque porte en utilise exactement une. Et ce qui persiste n'est jamais le même objet : un compte, un dossier, une branche, un magasin de sessions, un journal d'audit. C'est de cette troisième colonne que viennent la plupart des surprises.

3. Les quatre familles en bref

Les applications. Depuis le 16 septembre 2026, l'utilisateur ne choisit plus entre « chat » et « Cowork » : il y a un seul Claude, qui « determines what a task needs » ; le déploiement a commencé par les plans Pro et Max, Team et Free suivent, les organisations Enterprise ont au moins trente jours de préavis [S5]. L'application de bureau ajoute l'accès aux dossiers accordés, un navigateur intégré et, en bêta, l'usage de l'ordinateur. L'extension Chrome lit, clique et navigue dans votre navigateur avec vos sessions ouvertes ; les compléments Office partagent une conversation entre Excel, PowerPoint, Word et Outlook. Les plans vont de Free (chat seul, Sonnet et Haiku) à Pro (20 $ par mois, avec Claude Code, Chrome et Office), Max (dès 100 $, avec du crédit API inclus), Team et Enterprise [S4].

Claude Code. Six surfaces pour un seul moteur : le terminal, le plus complet ; l'onglet Code de l'application de bureau ; VS Code et JetBrains ; le web, où les sessions tournent dans le nuage et « continuent après que vous vous êtes déconnecté » ; le mobile, qui n'est qu'un client [S3]. La ligne décisive sépare les surfaces locales, ancrées dans un dossier, des sessions cloud, ancrées dans un dépôt GitHub cloné dans une machine virtuelle d'Anthropic. Autour, cinq façons de travailler loin de son terminal : Dispatch, Remote Control, Channels, Slack et les Routines, ces dernières étant des invites enregistrées qui tournent sur un horaire, un appel HTTP ou un événement GitHub, en sessions cloud autonomes [S3].

La plateforme. Deux façons de construire : l'API Messages, où votre code écrit sa propre boucle d'agent, et Managed Agents, où Anthropic héberge la boucle, le bac à sable et l'état des sessions, en bêta [S2]. Entre les deux, l'Agent SDK emparquette le moteur de Claude Code en bibliothèque Python ou TypeScript ; un produit bâti dessus doit s'authentifier avec une clé API, jamais avec l'abonnement d'un utilisateur.

Les revendeurs. Les mêmes quatre modèles sont vendus sur Bedrock, l'Agent Platform de Google et Foundry, avec l'identité, la facturation et les journaux d'audit de chaque fournisseur. Ce qu'on y perd est publié sur une seule page de documentation, la plus utile de toute la carte pour un acheteur : tout ce qui tourne en local fonctionne partout ; tout ce qui vit dans le nuage d'Anthropic (sessions cloud, mobile, Slack, Routines, Remote Control, Chrome, usage de l'ordinateur, artefacts) exige un compte claude.ai et n'existe chez aucun revendeur ; certaines capacités serveur varient (la recherche web est absente sur Bedrock, le mode rapide et l'Advisor n'existent que chez Anthropic) [S2]. Le premier canal reçoit chaque fonction en premier ; les revendeurs en portent un sous-ensemble qui grandit.

4. Où vit le contexte : un dossier ou un compte

La distinction la plus utile n'est pas une question de fonctions. Une session Claude Code locale est ancrée dans un dossier : le dossier porte les consignes permanentes dans CLAUDE.md, les réglages et les skills sous .claude/, l'historique git, les outils installés. Changez de dossier, vous changez de contexte. Une session de chat ou une session cloud est ancrée dans un compte : mémoire, préférences, projets, skills de compte et connecteurs se chargent au départ de chaque conversation sans qu'on le demande ; ce qui ne survit pas, c'est le disque de travail, un conteneur effacé à la fin de la session. Un CLAUDE.md n'y est lu que si un dépôt ou un dossier est attaché, parce que le mécanisme a besoin d'un répertoire de départ.

D'où une règle simple. Mettez ce qui concerne un projet dans un CLAUDE.md à la racine de son dépôt : il s'appliquera à l'identique dans un terminal, une session cloud, une Routine ou un processus de l'Agent SDK. Mettez ce qui vous concerne, quel que soit le projet, dans la mémoire du compte ou dans une skill : cela vous suivra sur le chat, le bureau, le téléphone et l'extension. Les deux mécanismes se complètent ; seule l'ancre par défaut diffère.

5. Qui paie, où vont les données

Un abonnement achète un ensemble de surfaces sous des fenêtres d'usage glissantes, avec un dépassement mesuré en option. La consommation achète des jetons, à des tarifs publics par million, avec le traitement par lots à moitié prix et, chez les revendeurs, une prime de 10 % pour les points de terminaison régionaux [S4]. Le crédit de « sessions cloud » offert en septembre 2026 illustre la logique : 100 $ pour Pro, 250 $ pour Max, valable jusqu'au 4 novembre, qui « covers cloud sessions only » et ne couvre ni les projets, ni les Routines, ni le chat, ni les sessions authentifiées par clé API ou via un nuage tiers ; après épuisement, les sessions cloud comptent dans les limites du plan « just like local sessions » [S6]. Ce n'était pas un produit nouveau, mais la subvention d'un seul chemin de déclenchement.

Pour les données, la ligne passe entre conditions grand public et conditions commerciales, non entre surfaces. Sur Free, Pro et Max, chaque utilisateur choisit si ses conversations peuvent servir à améliorer les modèles, le choix couvre Claude Code, et la conservation suit : cinq ans si oui, trente jours sinon. Sous conditions commerciales (Team, Enterprise, API, nuages tiers), Anthropic n'entraîne pas ses modèles sur les données, la conservation est de trente jours, et la rétention nulle est réservée aux comptes qualifiés [S7]. Chez les revendeurs, la télémétrie vers Anthropic est désactivée par défaut, et les déploiements Foundry hébergés sur Azure gardent invites et réponses dans Azure [S7]. Les sessions cloud, elles, conservent la transcription chez Anthropic pour pouvoir être reprises de n'importe quel appareil.

6. Choisir en quatre questions

  1. Le travail a-t-il besoin de votre machine ? Fichiers locaux, outils installés, réseau d'entreprise, navigateur connecté : une surface locale de Claude Code, l'extension Chrome ou le complément Office [S3].
  2. Doit-il survivre à la fermeture de l'ordinateur ? Une session cloud, une Routine, Claude Tag ou, pour qui construit une application, Managed Agents ; tous exigent le canal direct d'Anthropic [S2].
  3. Qui le déclenche ? Une personne en conversation : l'application ou une session cloud. Un horaire ou un événement : une Routine (abonnement) ou un déploiement planifié de Managed Agents (API). Votre propre code : l'API, l'Agent SDK ou le mode non interactif de Claude Code avec une clé API.
  4. Qui doit être facturé, et où les données doivent-elles rester ? Votre facture cloud et vos régions : Bedrock, l'Agent Platform ou Foundry, en acceptant le sous-ensemble de fonctions [S2]. Sinon, un abonnement pour les personnes et une clé API pour les machines.

Limites. Cette version condensée reprend l'entrée anglaise sans en reproduire les vingt-sept sources ni le détail des plans ; elle a été écrite le même jour, d'après les mêmes pages. Les prix sont les prix catalogue en dollars, hors taxes et négociation. Plusieurs fonctions décrites sont en bêta ou en avant-première, et la carte doit être relue sur les pages vivantes avant toute décision d'achat.
